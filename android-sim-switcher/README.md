# SIM Data Switcher (Android)

Automatically switches the **mobile-data SIM** on a dual-SIM Android phone when
the active SIM loses internet or drops to a weak signal — so you keep a working
data connection without manually digging into Settings.

> Branch: `claude/dual-sim-network-switching-q2gih9`

## Why it works this way (important)

Android does **not** let a normal app change the default data subscription
programmatically. The relevant API (`setDefaultDataSubId` / `MODIFY_PHONE_STATE`)
is reserved for system apps signed with the platform key. iOS forbids it entirely.

So this app uses the **no-root accessibility approach**: it detects the problem,
opens the system mobile-network settings, and taps the target SIM for you via an
`AccessibilityService`. This is the only way a sideloaded/Play-Store app can do
auto-switching on a stock, unrooted device.

> ⚠️ The Settings UI layout differs by manufacturer (AOSP, One UI, MIUI, ColorOS…).
> The node matchers in `SettingsNavigator.kt` are heuristic and may need tuning
> per device. When a switch can't be completed automatically, the app reports a
> failure so you can switch manually.

## Architecture

```
NetworkQualityMonitor ──▶ SwitchDecisionEngine ──▶ SwitchRequestBus ──▶ SimSwitchAccessibilityService
 (signal + validated         (pure, testable          (in-process            (drives Settings UI to
  internet + active           debounce/cooldown         hand-off)              select the target SIM)
  reachability probe)         logic)
        ▲                                                                              │
        └──────────────── SimMonitorService (foreground loop) ◀── results ────────────┘
```

| Component | Responsibility |
|-----------|----------------|
| `core/SimInfoProvider` | Read active SIMs + current data subscription (`SubscriptionManager`). |
| `monitor/NetworkQualityMonitor` | Combine connectivity validation, signal level, and an active HTTP-204 reachability probe bound to the cellular network. |
| `core/SwitchDecisionEngine` | Pure decision logic with a *failure window* (anti-flap) and *cooldown* (anti-ping-pong). Fully unit-tested. |
| `service/SimMonitorService` | Foreground service running the evaluate loop. |
| `service/SwitchRequestBus` | In-process channel between the monitor and the accessibility service. |
| `accessibility/SimSwitchAccessibilityService` | Performs the switch by navigating Settings. |
| `data/SettingsRepository` | Persists user thresholds via DataStore. |
| `ui/MainActivity` | Compose control panel: permissions, accessibility, primary SIM, thresholds, start/stop. |

## Permissions

- `READ_PHONE_STATE` — list SIMs / read signal & default data sub.
- `ACCESS_NETWORK_STATE`, `INTERNET` — connectivity callbacks + reachability probe.
- `FOREGROUND_SERVICE` (+ `SPECIAL_USE`), `POST_NOTIFICATIONS` — persistent monitoring.
- `BIND_ACCESSIBILITY_SERVICE` — the auto-switch executor.
- `RECEIVE_BOOT_COMPLETED` — resume monitoring after reboot (only if enabled).

## Setup flow (in-app)

1. Grant phone permission.
2. Enable the **SIM Data Switcher** accessibility service in system settings.
3. Pick your **primary** SIM and tune the signal / internet thresholds.
4. Tap **Start auto-switching**.

## Build

```bash
cd android-sim-switcher
./gradlew :app:assembleDebug   # build the APK
./gradlew :app:testDebugUnitTest   # run decision-engine unit tests
```

(The Gradle wrapper jar/scripts are generated by `gradle wrapper` if not present.)

## Limitations & next steps

- OEM-specific Settings navigation needs per-device matchers (see `SettingsNavigator`).
- Pre-Android 12 signal monitoring uses a deprecated listener and is currently a no-op
  (the validated-internet + reachability signals still work).
- A rooted variant could switch instantly via `su` shell calls instead of the UI —
  swap the accessibility executor for a root executor behind the same `SwitchRequestBus`.
